# 总体 E-R 图表达关键业务联系

- 以已实现的前后端行为核对关键业务联系，SQL 辅助核验，不以缺少操作人字段或关系可推导为由直接排除联系。理由：业务参与与数据库保存历史的方式不同，仅按外键画图会遗漏管理员维护等实际行为。
- 采用矩形实体、菱形联系、全单直线和线内基数，不画属性椭圆；可选性写入正文及联系清单。理由：保持总图记法一致，控制缩入论文版心后的标注密度。
- 管理员与医生按业务角色建模，管理类多对多联系不宣称已实现历史关联表。理由：共享登录表不能抹去角色职责差异，概念联系也不等于已有物理表。
- 主图保留关键业务并保持连通，其余联系及基数依据对照当前正文第四章与业务模型 `docs/diagrams/figure-4-7-business-model.json` 核对。理由：总览图需要可读，完整论证仍应可追溯——正文第四章承载论证过程，业务模型 JSON 是可机读的模型源（`gen_business_er.py` 的直接输入），两者都能逐条复核，也不会随图号调整失效。

本决定取代 ADR-0003、ADR-0005。图号以当前正文题注为准，不沿用早期图4-5编号。
